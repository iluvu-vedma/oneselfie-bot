# Копирайт OneSelfie: правила и разбор правок

Вычитка от 20.08.2026. Правился только текст, который видит пользователь.
Логика сценария, `callback_data`, сигнатуры хендлеров и экономика не тронуты.

Все экраны печатаются без запуска бота:

```bash
npm run screens
```

## Глоссарий

Одно слово на сущность во всём боте. Синонимы из правой колонки не употребляются
нигде — ни в текстах, ни в кнопках, ни в описаниях команд.

| Сущность | Термин | Нельзя |
|---|---|---|
| Что присылает пользователь | **селфи** (ед. — «фото») | кадр, снимок, изображение |
| Что выдаёт бот | **кадр** | фото, картинка, результат, генерация |
| Внутренняя валюта | **искры ✨** | монеты, баллы, кредиты |
| Валюта Telegram | **звёзды ⭐** | Stars, XTR |
| Набор искр за звёзды | **пакет** | тариф, набор, план |

Главная ловушка: до правок «кадр» означал и присланное селфи («чем больше кадров —
тем точнее сходство»), и товар за 12 ✨. Между этими двумя экранами один шаг.
Слово «кадр» теперь занято товаром и только им.

## Тон

- Обращение на **«вы»**, без имени.
- Бот о себе — **в первом лице единственного числа**: «вернул», «убрал», «выбираю
  сам». Никаких «мы»: за ботом стоит один человек, и в момент возврата денег это плюс,
  а не минус.
- **Кнопка**: с заглавной, без точки, глагол + объект или голые числа, ≤ 25 символов.
- **Точка** в конце обычных сообщений — да; у коротких статусов («2 из 4 ✓»,
  «Баланс: 180 ✨ · 15 кадров») — нет.
- **Эмодзи только функциональные**: ✨ ⭐ ✓. Декоративных нет.
- Числа 1–4 в инструкциях прописью («от одного до четырёх»), цены и счётчики — цифрами.
- **Ошибка называет причину и следующий шаг.** «Что-то пошло не так» запрещено.
- Валюта: значок ✨ по умолчанию, словом («12 искр ✨») — только там, где человек
  встречает её впервые: заголовок пейволла и описание счёта. За это отвечает
  `sparksNamed()` в `src/ui.ts`.
- Разметки в текстах нет: пользовательские сообщения уходят без `parse_mode`
  (HTML стоит только у `/stats`). Появится разметка — экранировать придётся всё.

## Три решения, которые стоит помнить

**Кнопки пейволла: порядок и бонус.** Было «название · искры · звёзды · это N кадров
· +N ✨ в подарок» — до 53 символов, на узком экране хвост обрезается. Хуже длины
была арифметика: `p.sparks` уже включает бонус, поэтому «180 ✨ … +10 ✨ в подарок»
читалось как 190. Стало «кадры · искры · звёзды», 22–25 символов, бонус ушёл в текст
над кнопками («чем больше пакет, тем больше искр за звезду» — правда: 1.00 / 1.06 /
1.09 искры за звезду). Проверка `check-economy.ts:56` требует, чтобы на кнопке
остались и ✨, и «кадр» — остались.

**`notEnough` считает недостачу, а не остаток.** Строка приходит и при нулевом
балансе, где «у вас 0 ✨» выглядело как сбой. Плюс в подписи под кадром
(`deliver.ts:32-34`) она клеится к `T.ready`, и баланс назывался дважды подряд.
Теперь `T.ready` отвечает за остаток, `T.notEnough` — за недостачу, числа разные и
не спорят: «Баланс: 5 ✨ · 0 кадров» + «До кадра не хватает 7 ✨. Выберите пакет:».
Так открытый вопрос про склейку закрылся текстом, без правки `deliver.ts`.

**«Кадр будет другой» в сообщении о провале — это правда.** `nextSceneIndex` к моменту
возврата уже сдвинут, повтор возьмёт следующую сцену из пула. Если пул когда-нибудь
станет фиксированным, фразу надо убрать.

## Открытые вопросы

1. **`T.alreadyGenerating` по-прежнему мёртвая** (`ui.ts:122`). При двойном тапе
   уходит `T.generating` — «Готовлю кадр, 30–60 секунд», и человек думает, что
   запустил второй кадр. Чинится одной строкой в `flow.ts:73`; по вашему решению не
   трогал.
2. **Названия пакетов теперь дублируют арифметику.** `title: "15 кадров"` верно, пока
   `sparks / SPARKS_PER_IMAGE = 15`. Если когда-нибудь поменяется цена кадра или состав
   пакетов — названия надо переписать руками. Стоит добавить эту проверку в
   `check-economy.ts` (одна строка `check(p.title === frames(...))`), но это код, и я
   её не добавлял.
3. **`EXAMPLE_IMAGE_URL` пуст** — шаг 2 уходит текстом. Новый `intro` написан так,
   чтобы работать и без картинки, но обещание «студия, улица, вечерний город» без
   примера проверить нечем. Это по-прежнему главный неготовый экран воронки.
4. **`/stats` не тронут** — по вашему решению. Внутри английские ключи воронки
   (`photos_uploaded`, `paywall_shown`); читатель один, но если появится второй, экран
   придётся переписать.
5. **Уведомления владельцу** (`notifyOwner`, 7 штук) остались как есть — служебные.
6. **`MIN_PHOTOS` в `config.ts` не используется нигде.** К текстам отношения не имеет,
   но заметил при инвентаризации.

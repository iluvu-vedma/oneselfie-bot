# Интерфейс OneSelfie

Переработка от 24.08.2026 под CLAUDE.md. Экономика, модель, пакеты, промпт и
логика идемпотентности не тронуты — менялись навигация, экраны и тексты.

Все экраны печатаются и проверяются без запуска бота:

```bash
npm run screens
```

## Модель навигации: один экран — одно сообщение

Весь интерфейс живёт в **одном сообщении**, которое редактируется. Нажатие
кнопки правит то самое сообщение, на котором она стоит. Чат не растёт.

Новое сообщение отправляется ровно в четырёх местах, и каждое — отдельный объект
в ленте, а не экран:

| Что | Почему отдельным сообщением |
|---|---|
| Картинка-пример при первом `/start` | подарок на входе, к нему возвращаются |
| Счёт Telegram | это объект Telegram, внутрь экрана его не положить |
| Готовый кадр | его пересылают и сохраняют |
| `/stats` владельца | служебное, не часть продукта |

После каждого такого объекта экран **переезжает вниз**: старый удаляется, новый
отправляется под ним. Иначе экран остаётся выше и его не видно.

Реализация — `src/hub.ts`, три функции:

| Функция | Когда |
|---|---|
| `draw(chatId, screen)` | перерисовать на месте, ctx недоступен (коллбэк kie, крон) |
| `drawHere(ctx, screen)` | перерисовать сообщение с нажатой кнопкой |
| `move(chatId, screen)` | перенести вниз: в ленте появился новый объект |

`drawHere` **усыновляет** сообщение: если человек нажал кнопку на старой копии
экрана далеко вверху чата, эта копия и становится экраном. Отдельной ветки
«меню устарело» не нужно — экран собирается целиком из состояния, расхождению
взяться неоткуда.

## Карта

Экранов два. Корень рендерится из состояния, «Назад» на нём нет.

```
home                                             корень, четыре стадии
├─ start   селфи нет            ● Пополнить баланс — от 60 ⭐   → paywall
├─ need    селфи есть, искр нет ● Пополнить баланс              → paywall
│                               · Заменить селфи                → home
├─ ready   всё на месте         ◆ Сделать кадр — 12 ✨          → home:busy
│                               · Пополнить баланс  · Заменить селфи
└─ busy    идёт генерация       кнопок нет

paywall                                          ● 5 кадров · 60 ✨ · 60 ⭐
                                                 ● 15 кадров · 180 ✨ · 170 ⭐
                                                 ● 30 кадров · 360 ✨ · 330 ⭐
                                                 · ⊗ Назад                → home
```

`◆` синяя (`primary`), `●` зелёная (`success`), `·` без стиля.

Стадия **выводится из KV целиком**, отдельного флага «где мы сейчас» нет:
`busy` — по замку генерации, `start` — по нулю селфи, `need` — по балансу ниже
цены кадра. Поэтому `home` рисуется в любой момент и всегда одинаково: после
оплаты, после кадра, из аварийного крона, спустя сутки.

## Что убрано и почему

**Экран «Начать».** Нёс один тап и ноль информации. Приветствие и просьба о селфи
теперь один экран.

**Кнопка «Готово» после селфи.** Одного селфи уже достаточно, а экран после
каждого фото сам переезжает вниз в новом состоянии. Отдельное подтверждение
только держало человека на кнопке, которая ничего не решает.

Глубина до оплаты — **2 нажатия** вместо 4.

**Клавиатуры под кадром и под сообщением о возврате.** Кадр уходит без подписи и
без кнопок, всё управление — на экране под ним. Отдельного сообщения об ошибке
тоже нет: возврат виден первой строкой экрана, рядом с балансом и кнопкой
повтора. Человеку нужны две вещи сразу — что деньги на месте и что делать дальше.

## Тексты

Ни одной строки в коде: всё в `locales/ru.json`, в коде только ключи. Ключи по
экранам (`home.ready.body`, `paywall.offer.item`, `button.back`).

Локаль одна. Мультиязычность — фича, а фичи заморожены до первой оплаты; всё,
что нужно второй локали, уже на месте: добавляется файл и строка в `BUNDLES`.

Плюрализация — через `Intl.PluralRules`, а не через `if (n === 1)`: формы лежат
в JSON рядом со строками (`unit.frame`, `unit.spark`, `unit.selfie`). Числа —
через `Intl.NumberFormat`.

Отсутствующий ключ не фолбэчится молча. Промах виден трижды: в тексте (`⟨key⟩`),
в логе и в `npm run screens`, который на непустом множестве промахов падает.

Оффер про бонусные искры собирается из `PACKAGES`, а не пишется руками:
поменяется состав пакетов — текст поедет за ним, а не соврёт.

### Глоссарий

Одно слово на сущность. Синонимы из правой колонки не употребляются нигде.

| Сущность | Термин | Нельзя |
|---|---|---|
| Что присылает пользователь | **селфи** (ед. — «фото») | кадр, снимок, изображение |
| Что выдаёт бот | **кадр** | фото, картинка, результат, генерация |
| Внутренняя валюта | **искры ✨** | монеты, баллы, кредиты |
| Валюта Telegram | **звёзды ⭐** | Stars, XTR |
| Набор искр за звёзды | **пакет** | тариф, набор, план |

Слово «кадр» занято товаром и только им. До вычитки 20.08 оно означало и
присланное селфи, и товар за 12 ✨ — между этими экранами один шаг.

### Тон

- Обращение на **«ты»**, имя — только в приветствии. До 24.08 было «вы»;
  CLAUDE.md задаёт «ты», и это единственная причина смены.
- Бот о себе — **в первом лице единственного числа**: «вернул», «убрал»,
  «выбираю сам». Никаких «мы»: за ботом стоит один человек, и в момент возврата
  денег это плюс.
- Разметка — `parse_mode: "HTML"` везде. MarkdownV2 не используем. Имя
  пользователя проходит через `esc()`.
- Иконки — узкий постоянный набор: `✋ 📸 🎬 ⏳ ⭐ 🎁` в заголовках блоков,
  `✨ ⭐ ✓ ⊗ ⌄` внутри строк. Каждая называет блок, ни одна не украшает.
- Ошибка говорит, **что делать дальше**, и снимает главный страх: деньги на месте.

## Проверки Definition of Done

`npm run screens` печатает все экраны и валит прогон, если нарушен любой пункт
из CLAUDE.md:

- мостик `⌄` в последней строке у экрана с клавиатурой;
- кнопок ≤ 8, лейбл ≤ 30 символов;
- `callback_data` латиницей и ≤ 64 байт;
- не больше двух `primary`, хотя бы одно главное действие;
- «Назад» один, отдельным рядом, внизу — и его нет на корне;
- нет экрана, единственная кнопка которого «Назад»;
- в тексте нет markdown и нет тегов вне списка Telegram HTML;
- текст ≤ 4096 символов;
- ни одного промаха по ключам локали.

`npm run check` дополнительно гоняет `check-flow.ts` — весь сценарий на
заглушках Telegram, KV и kie. Он проверяет то, чего не видно в статике: сколько
сообщений остаётся в ленте после каждого шага и где стоит рабочий экран.

## Открытые вопросы

1. **`EXAMPLE_IMAGE_URL` пуст** — при первом `/start` картинки-примера нет.
   Экран написан так, чтобы работать и без неё, но обещание «студия, улица,
   вечерний город» проверить нечем. По-прежнему главный неготовый экран воронки.
2. **Гонка при альбоме из четырёх селфи.** Каждое фото переносит экран вниз;
   четыре параллельных обработчика теоретически могут оставить наверху лишнюю
   копию. Она безвредна: клавиатура снимается до удаления, а нажатие на любую
   копию усыновляет её как текущий экран. На живом трафике не воспроизводилось —
   заливка селфи в kie занимает около секунды и разносит обработчики во времени.
3. **`MIN_PHOTOS` в `config.ts` не используется нигде.** «От одного до четырёх»
   написано в локали словами по правилам копирайта.
4. **`/stats` не тронут** — внутри английские ключи воронки, читатель один.
5. **Уведомления владельцу** (`notifyOwner`) остались служебными и на «вы» не
   проверялись: их читает только владелец.

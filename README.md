# OneSelfie

Четыре нейросети для картинок в одном чате. Сценарий целиком:
`/start` → модель → своё фото **или** описание словами → промпт → кадр → повтор
в одно нажатие.

Бот: [@OneSelfie_bot](https://t.me/OneSelfie_bot)

Весь интерфейс — **одно сообщение, которое редактируется**. Экранов одиннадцать:
`home`, `models`, `model`, `upload`, `prompt`, `describe`, `busy`, `topup`,
`packs`, `help`, `earn`. Отдельными сообщениями уходят только кадр, счёт Telegram
и картинка-пример при первом старте — после каждого экран переезжает вниз.
Карта переходов, экономика и тексты: [docs/interface-v2.md](docs/interface-v2.md).

## Модели и цены

| Id | Модель | Цена | Бери, когда |
|---|---|---|---|
| `nbpro` | Nano Banana Pro | 20 ✨ | кадр идёт в дело |
| `sd5` | Seedream 5 Pro | 15 ✨ | важна атмосфера |
| `nb2` | Nano Banana 2 | 12 ✨ | работаешь со своим лицом |
| `gpt2` | GPT Image 2 | 10 ✨ | в кадре много условий |

Курс: **1 ✨ = 1 ⭐ = 1,5 ₽**. Реестр моделей и пакетов — `src/config.ts`,
экраны собираются из него. Арифметику проверяет `npm run check`.

## Чего не хватает для запуска

| Что | Где взять | Без этого |
|---|---|---|
| **Слаги моделей в kie** | каталог kie.ai | три из четырёх моделей не считают |
| `KIE_API_KEY` | kie.ai → API keys | генерация не работает |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | Upstash free tier или Vercel KV | бот падает на старте |
| `PUBLIC_URL` | адрес деплоя на Vercel | kie некуда стучаться |
| `OWNER_CHAT_ID` | напишите боту, посмотрите логи | нет `/admin`, `/stats` и лога провалов |
| `ADMIN_IDS` | chat_id помощников через запятую | админка только у владельца |
| `CHANNEL_URL`, `PROMPTS_CHANNEL_URL` | адреса каналов | кнопки не рисуются вовсе |
| `SUPPORT_URL` | ссылка на личку | в справке нет строки «куда писать» |
| `EXAMPLE_IMAGE_URL` | **сетка ваших реальных результатов** | вход без примера, одним текстом |
| Внешний эквайринг | провайдер не выбран | живы только звёзды, остальное — тост «скоро» |
| Шаг 0 из ТЗ | 5 генераций своего лица в плейграунде kie | оффер не проверен |

**Слаги kie проверены не все.** В бою жил только `nano-banana-2`; остальные три
(`nano-banana-pro`, `seedream-5-pro`, `gpt-image-2`) выписаны по названиям и
требуют сверки с каталогом. Неверный слаг ломает не деньги, а модель: `createTask`
падает, искры возвращаются сами, человек видит «не получилось запустить кадр».

**Отличия моделей глазами не проверены.** Строки `about`, `pick` и `weak` в
`locales/ru.json` — гипотеза. Один общий промпт на четырёх моделях закрывает
вопрос за полчаса; до тех пор бот обещает разницу, которой может не быть.

**Шаг 0 остаётся невыполненным.** Режим «моё фото» написан под допущение
«непохожесть лечится промптом» — за это отвечает `PROMPT_PREFIX` в `src/config.ts`.

```

src/ledger.ts    журналы: история операций, лог сбоев, лог начислений, кольцо ошибок
src/prompt.ts    промпт человека: нормализация, преамбула, подпись под кадром

src/ui.ts        валюта в строках, схема callback_data, клавиатуры со style

src/hub.ts       навигация в одном сообщении: draw / drawHere / move / album
src/flow.ts      адреса экранов (Ref), сборка из KV и запуск генерации
src/deliver.ts   выдача кадра с промптом в подписи и возврат искр
src/stats.ts     счётчики за всё время и за сегодня, дашборд, здоровье и /stats
src/admin.ts     роутер админки: доступ, поиск людей, движение искр
```

Смена модели, цены кадра или состава пакетов — правка **только** `src/config.ts`.
Правка любого текста — **только** `locales/ru.json`.

### Схема `callback_data`

```
nav:home · nav:models · nav:model:<id> · nav:topup:<откуда> · nav:help · nav:earn
gen:photo · gen:text · gen:reset · gen:photos
pay:<рельс> · buy:<рельс>:<пакет>

adm:home · adm:health · adm:fails · adm:users · adm:find
adm:u:<id> · adm:p:<id> · adm:r:<id> · adm:s:<id>:<причина> · adm:c:<id>:<причина>
adm:g:<id>:<причина>:<сумма>
```

Общего `nav:back` нет: «Назад» несёт адрес места назначения. Исключение —
пополнение: откуда человек в него пришёл, из адреса не видно, поэтому источник
едет прямо в `nav:topup:*` и дублируется в состоянии, чтобы пережить оплату.

Второе исключение — админка: чей баланс правим, едет в самом адресе кнопки,
хотя это же лежит и в состоянии. Правило «в callback только то, чего нет в
сессии» тут уступает деньгам: сумма обязана уйти тому, чьё имя админ видел
на этом экране, даже если экран уже уехал вверх по чату.

## Админка

`/admin` — владельцу и всем, кто перечислен в `ADMIN_IDS`. Проверка доступа
одна на весь роутер и стоит на входе, отдельных веток снаружи нет.

```
admin            дашборд: воронка по людям, деньги, кадры, «сегодня»
  admin.health   очередь, время кадра, отказы kie, последние ошибки
  admin.fails    лог сбоев: кто, когда, чем, сколько списано, ушёл ли возврат
  admin.users    последние зарегистрированные
  admin.find     поиск по числовому id или @username
  admin.user     карточка целиком: профиль, баланс, история операций, сбои
    admin.photos   селфи человека альбомом — по кнопке, отдельным объектом
    admin.reason   за что начисляем — поле обязательное
    admin.amount   сколько: лестница сумм или своё число
```

Дашборд и здоровье разнесены нарочно: первый смотрят с утра и он про то, как
идут дела, второй открывают по жалобе и он отвечает на один вопрос — работает
бот сейчас или тонет.

Селфи человека открываются только из карточки и только пока живы ссылки —
kie держит файлы около суток, и без них кнопки нет вовсе. Каждый просмотр
уходит в лог поимённо: доступ есть у всех из `ADMIN_IDS`, и вопрос «кто
смотрел» обязан иметь ответ. Человеку про просмотр не пишется.

От корня до возврата денег три нажатия: `сбои → карточка → кнопка с суммой`.
Кнопка быстрого возврата гаснет, как только за этот сбой начислили, — экрана
подтверждения у операции нет намеренно, и двойное нажатие не должно платить
дважды. Ошибочное начисление откатывается кнопкой «Списать», обе операции
лежат в журнале рядом.

Начисление человек видит отдельным сообщением, списание проходит молча:
почти всегда это откат ошибки, и объяснять его в личке нечем.

Данные, которых до админки в KV не было:

```
led:<id>   история операций человека, новые сверху, хранится 50
fails      общий лог сбоев, хранится 100
fl:<id>    личный лог сбоев, хранится 10
grants     кто, когда, кому, сколько и почему начислил, хранится 100
errors     кольцо последних ошибок: когда, где, rid, текст; хранится 50
lock:<id>  очередь на чат: один пишущий в экран за раз
users      индекс людей: score = дата регистрации
un:<name>  @username → chat_id; у Bot API такого метода нет, индекс свой
adm:<id>   состояние админа: кого смотрим, чего ждём текстом, куда вернёт «Назад»
stat:<событие>:<дата>  дневной счётчик, живёт 45 дней
```

Юзернейм в Telegram можно сменить и отдать другому, поэтому найденный по
индексу профиль обязан подтвердить юзернейм сам — иначе искры уехали бы не тому.

## Развёртывание

```bash
npm install
```

Затем скопировать `.env.example` в `.env`, заполнить и прогнать проверки:

```bash
npm run check
```

`vercel.json` объявляет `outputDirectory: public`, а `public/index.html` — заглушка.
Build-командой стоит `tsc --noEmit`: она ничего не эмитит, и без существующей
выходной директории Vercel роняет деплой. Папку `public` не удалять.

Деплой на Vercel, затем в переменные окружения проекта кладётся всё то же,
что в `.env`, плюс `PUBLIC_URL` = адрес деплоя. После деплоя:

```bash
npm run set-webhook
```

## Крон

Аварийный добор нужен через 90 секунд, а таймаут-возврат — через 5 минут.
**Тариф Hobby разрешает крон только раз в сутки**: выражение чаще суточного
роняет деплой с ошибкой `Hobby accounts are limited to daily cron jobs`.

Поэтому в `vercel.json` крон стоит на `0 3 * * *` — это последняя страховка,
а не рабочий путь. Минутный добор вешается снаружи:

- cron-job.org (или любой другой планировщик), каждую минуту на
  `https://<домен>/api/sweep`;
- секрет передавать заголовком `Authorization: Bearer <CALLBACK_SECRET>`,
  а не через `?secret=` — query-строка оседает в логах;
- альтернатива — тариф Pro, там `* * * * *` работает штатно.

Без минутного добора потеря коллбэка означает списанные искры без кадра —
ровно тот кластер жалоб, который нельзя повторять. Суточный крон сам по себе
от этого спасает лишь потому, что **запись задачи живёт двое суток**
(`TASK_TTL_SEC`): пока она жива, за задачу можно вернуть искры, а с её смертью
возврат становится невозможен навсегда. Уменьшать этот срок ниже двух приходов
крона нельзя — `check-state` на этом падает.

## Наблюдаемость

Логи пишутся одной строкой JSON, и у каждого события есть `rid`: один апдейт,
один коллбэк kie, один проход крона получают свой код. По нему из общей ленты
Vercel выдёргивается вся история события целиком — вместе с походом в kie
и отправкой в Telegram.

```json
{"lvl":"info","msg":"gen.started","rid":"a3f9d1","chatId":483920112,"kind":"cb:gen:text","model":"nb2","cost":12,"taskId":"…"}
```

В логи не попадают токены, ключи, промпты и ссылки на селфи: промпт — личное,
а ссылка на селфи открывается вообще без авторизации. Пишутся длина и количество.

Логи Vercel на бесплатном тарифе живут час, а вопрос «что вчера ломалось»
задают на следующий день, поэтому последние 50 ошибок лежат своим кольцом
в KV и показываются на экране `admin.health` вместе с очередью недобранных
кадров, средним временем кадра и отказами kie. Сбой генерации и ошибка
разведены: первое про то, кому должны искры, второе про то, что чинить.

## Устойчивость

- **Очередь на чат** (`src/queue.ts`). Апдейты одного человека приезжают
  в разные процессы одновременно: альбом из четырёх селфи — четыре запуска
  функции, а коллбэк kie приходит ровно тогда, когда человек жмёт кнопки.
  Через очередь проходит всё, что рисует экран: вебхук, коллбэк, крон.
  Плагин `sequentialize` из grammY тут бесполезен — он держит очередь в памяти
  процесса, а процесс у каждого апдейта свой.
- **Срок вебхука задан явно.** У grammY по умолчанию 10 секунд и
  `onTimeout: "throw"`: апдейт длиннее — Telegram получает пятисотку и шлёт его
  заново, то есть второй раз заливает то же селфи. Стоит 25 секунд при
  `maxDuration` 30 и ответ двухсоткой в любом случае.
- **Повтор запросов к Telegram.** 429 повторяется всегда и с паузой, которую
  Telegram сам назвал. 5xx — только у методов, не создающих новых объектов:
  повтор `sendMessage` может прислать человеку второй кадр.
- **Потолок ожидания kie** — 20 секунд. Зависшее соединение иначе съедает всю
  функцию, а человек всё это время смотрит в тишину.
- **GETDEL вместо GET плюс DEL** при переезде экрана вниз: между двумя
  командами помещается второй процесс, и тогда экран удаляют дважды.
- **Крон разгребает пачками** по 100 задач, по 5 одновременно: суточный крон
  обязан вычистить очередь за один приход, иначе следующая попытка завтра.
- **Кнопка от старой версии бота** получает внятный тост и свежий экран, а не
  вечные часики: у роутера есть ветка на неизвестный `callback_data`.

## Проверки

```bash
npm run check
```

`scripts/check-economy.ts` — нетто по каждому рельсу и пакету, правило 50% для
всех четырёх моделей, базовый размен 1 ✨ = 1 ⭐, курс 1,5 ₽, порядок цен и
запас по ставке эквайринга. Таблицы из `docs/interface-v2.md` §2б и §6 здесь
исполняемые.
`scripts/check-state.ts` — двойной тап, двойной коллбэк, единственный возврат,
единственное зачисление платежа, модель и промпт внутри задачи, мусор в KV,
сброс фото без потери баланса, запоминание и забывание id экрана, очередь на
чат под одновременным заходом, неделимость GETDEL и связь сроков между собой
(запись задачи переживает два прихода крона, замок чата — самый долгий
обработчик).
`scripts/check-flow.ts` — весь сценарий на заглушках Telegram, KV и kie: сколько
сообщений остаётся в ленте после каждого шага, что уходит в kie в каждом режиме,
куда человек попадает после оплаты и что альбом селфи — один объект в ленте,
а не пять.
`scripts/check-admin.ts` — админка на настоящем роутере grammY с подменённым
транспортом: три нажатия до возврата денег, обе записи в журналах, погасшая
после начисления кнопка, списание без ухода в минус, поиск по сменённому
юзернейму, отказ чужому, просмотр селфи из карточки и то, что промпт админа
панель не съедает.
`scripts/preview-screens.ts` — печатает все экраны и валит прогон при нарушении
Definition of Done из CLAUDE.md (мостик `⌄`, длина кнопок, `callback_data` и его
маршрут, «Назад», markdown в тексте, пропущенные ключи локали). Линтера в проекте
нет — эту роль выполняет он.

Экраны прогоняются и отдельно: `npm run screens`.
